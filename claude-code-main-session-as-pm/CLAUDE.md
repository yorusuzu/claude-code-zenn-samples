# プロジェクト名 — マルチエージェント運用テンプレート

このファイルは、Claude Code のメインセッションを「PM / オーケストレーター」として固定し、
複数のサブエージェント（`.claude/agents/`）に仕事を分担させるための最小テンプレートです。
自分のプロジェクトにコピーして、役割名・ディレクトリ名を実際のワークフローに合わせて書き換えてください。

## 運用方針: メインセッションが仕切る

サブエージェントを複数追加すると、次の問題が起きやすくなります。

- どのエージェントが何を最終的に判断するのかが決まっておらず、指示が重複する
- 各エージェントの成果物がどこに置かれるべきか曖昧になり、探すコストが増える
- 直列で進めるべき作業が並行で走り、前工程の成果物がないまま次工程が始まる

これを避けるため、**メインセッション（あなたと直接会話しているセッション）を PM / オーケストレーターに固定**します。
メインセッションは自分では専門作業をせず、次だけを行います。

1. 各サブエージェントに仕事を割り振る
2. サブエージェント間の成果物をファイル経由で受け渡す（各サブエージェントの `tools` に `Agent` を含めていない場合、そのサブエージェントは他のサブエージェントを直接呼べないため。`tools` を省略すると `Agent` も継承され、サブエージェントが別のサブエージェントを起動できる点に注意）
3. 標準ワークフローの進行状況を追跡する
4. 人間の承認が必要な操作（公開・送信・決済など）の前で必ず止まる

## 組織（.claude/agents/）

役割ごとにサブエージェントを分け、担当と出力先を 1 つの表にまとめておくと、
メインセッションが「次に誰に何を頼むか」を毎回迷わず判断できます。

| エージェント | 役割 | 主な出力先 |
|---|---|---|
| researcher | 調査・情報収集、根拠となるデータ集め | `research/` |
| writer | 調査結果をもとにした制作物（記事・コード・文書など）の作成 | `drafts/` |
| reviewer | 事実確認・品質チェック（合否判定のみ、編集はしない） | `reviews/` |

実プロジェクトでは、この 3 役に加えて「企画」「実装検証」「公開後の計測」などを
必要に応じて追加してください（分割の基準は「出力先が違う」「専門知識が違う」「再利用したい単位」）。

## 標準ワークフロー

1. 調査（researcher）→ `research/<slug>.md`
2. 制作（writer）→ `drafts/<slug>.md`
3. レビュー（reviewer、不合格なら writer に差し戻し）→ `reviews/<slug>.md`
4. **公開承認**: 公開・送信・デプロイ対象の一覧をユーザーに提示し、明示的な「OK」をもらう
5. 承認後にのみ、公開・デプロイ作業を行う

## ガードレール（必須）

- 成果物は既定で非公開・下書き状態のまま作る。公開（外部への送信・デプロイ・投稿）はユーザーの承認後のみ行う。承認は 1 回ごと・対象を明示してもらう。
- アカウント作成、本人確認、決済情報の入力、規約への同意は AI が行わない（ユーザー本人のみ行う）。
- 誇大表現・架空の実績・根拠のない数字・他者著作物の無断転載をしない。
- API キー・個人情報をリポジトリにコミットしない。

## ディレクトリ

```
research/     調査レポート
plans/        企画書
drafts/       制作物（記事・コードなど）
reviews/      レビュー結果
```

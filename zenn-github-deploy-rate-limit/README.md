# check-publish-count.mjs（Zenn の記事を push する前に、直近 24 時間の公開数を数える）

Zenn の GitHub 連携で運用しているリポジトリで、直近 N 時間（既定 24 時間）に `published: true` になった記事の数を数えます。
件数が運用値（既定 1 本）以上なら警告し、「次に push してよい目安の時刻」を表示します。

Zenn は、記事の投稿数を直近 24 時間（予約投稿を含む）で制限しています（[Zenn の FAQ](https://zenn.dev/faq/rate-limit)）。
上限を超えると、push しても記事がデプロイされず、「投稿数の上限に達したためデプロイされませんでした」と通知されます。
このスクリプトは、その前に自分で気づくための道具です。

## 「24 時間に 1 本」は Zenn の公式の数値ではありません

- **Zenn が公開していること**: 記事は直近 24 時間の投稿数（予約投稿を含む）、本は直近 1 週間の投稿数で制限されること。一定の時間が経てば、再び投稿できるようになること。
- **Zenn が公開していないこと**: 上限の具体的な本数と、判定のロジック。
- **このスクリプトの既定値（1 本）**: 筆者のアカウントで、2 本を同時に公開にして、うち 1 本のデプロイが拒否されたことから決めた、安全側の運用値です。Zenn の上限そのものではありません。上限はアカウントや時期によって違う可能性があります。

運用値は `--limit` で変えられます。

## セットアップ

- Node.js（v24.18.0 で確認。標準モジュールだけを使うので、`npm install` は不要です）
- git（2.54.0 で確認）

`check-publish-count.mjs` を 1 ファイルだけ、Zenn 連携のリポジトリの直下などに置きます。

## 使い方

リポジトリの直下（`articles/` があるフォルダ）で実行します。

```sh
node check-publish-count.mjs
```

| 引数 | 既定値 | 意味 |
|---|---|---|
| `--repo <dir>` | カレントディレクトリ | 調べるリポジトリ。リポジトリの直下（`articles/` の親）を指定します |
| `--hours <n>` | `24` | 数える期間（時間） |
| `--limit <n>` | `1` | 運用値。この本数以上なら警告します |
| `--now <ISO8601>` | 実行した時刻 | 「今」を固定します（例: `2026-10-03T12:00:00+09:00`）。動作確認用です |

### 出力例

```text
直近 24 時間（2026-10-02 12:00:00 +09:00 から 2026-10-03 12:00:00 +09:00 まで）に公開した記事: 1 本
  - first-article（2026-10-03 10:00:00 +09:00）
NG: もう 1 本公開すると、運用値（24 時間に 1 本）を超えます
次に push してよい目安: 2026-10-04 10:00:00 +09:00 以降
```

時刻は、実行したパソコンのタイムゾーンで表示します。

### 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | 件数が `--limit` 未満（あと 1 本以上公開できる） |
| 1 | 件数が `--limit` 以上（もう 1 本公開すると運用値を超える。または、すでに超えている） |
| 2 | git の履歴を読めなかった（git のリポジトリではない、コミットが 1 つもない、など）。引数の誤り |

### いつ実行するか

このスクリプトが答えるのは、「今から、もう 1 本公開してよいか」です。
すでに `published: true` にした変更（未コミットのもの、コミットしたがまだ push していないもの）も、件数に入ります。

- 新しく `published: true` にする**前**に実行し、終了コードが 0 なら、1 本を公開します。
- `published: true` にした**後**に実行した場合、その記事も 1 本として数えられます。運用値が 1 本なら、その 1 本だけでも終了コードは 1 になります。このときは、表示された記事が今から push する 1 本だけかどうかを確認してください。2 本以上表示されたら、push を止めます。

## 数え方

- **対象**: `articles/*.md` だけです。本（`books/`）は数えません。
- **公開とみなすもの**: 先頭のフロントマター（`---` で囲んだ部分）の `published` が、`true` でない状態から `true` になった変更です。新しく `published: true` で追加したファイルも含みます。本文のコードブロックの中にある `published: true` の行は数えません。
- **コミット済みの変更**: 今のブランチを first-parent でたどり、コミットの時刻（committer date）が窓の中にあるものを数えます。窓は「`--now` の `--hours` 時間前より後、`--now` 以前」です。ちょうど 24 時間前のものは数えません。
- **マージ**: 別のブランチで公開してからマージした記事は、マージのコミットの時刻で数えます。
- **未コミットの変更**: `git diff HEAD`（ステージ済みを含む）と、まだ追跡していない新しいファイルを見て、`published: true` になっていれば「未コミット」として数えます。時刻は「今」とみなします。
- **同じ記事**: 窓の中で何度 `true` になっても 1 本と数えます。時刻は新しいほうを使います。
- **`false` に戻した記事**: 今の作業ツリーで `published: true` でない記事（`false` に戻した記事、削除した記事）は数えません。ただし、Zenn の側で、一度デプロイされた分がどう数えられるかは分かりません。
- **次に push してよい目安**: 件数が運用値を下回る時刻です。古い公開から順に窓の外へ出るとして計算します。たとえば運用値 1 本で 2 本が窓の中にあれば、新しいほうの公開から 24 時間後です。

## このスクリプトにできないこと

- **Zenn の判定とは一致しません。** Zenn が何を「投稿」として数えるか（公開済みの記事の更新を含むか、デプロイが拒否された分を含むか、など）は公開されていません。
- **コミットの時刻は、push の時刻でも、Zenn がデプロイした時刻でもありません。** コミットしてから時間をおいて push すると、実際より早い時刻で数えます（窓から早く外れるので、件数が少なく出ます）。
- **予約投稿（`published_at`）は数えません。** 予約した日時は見ていません。
- **本の「直近 1 週間」は数えません。**
- **リモートと比べません。** どのコミットがすでに push 済みかは見ていません。
- **コミットの日時を書き換えた履歴（rebase など）では、ずれます。** committer date を、そのまま信じます。
- **リポジトリの直下以外を `--repo` に指定した場合の動作は、確認していません。**
